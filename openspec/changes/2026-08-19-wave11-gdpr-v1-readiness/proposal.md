## 12. Migration Path

**4 new schema migrations** + 1 modified migration:

- **11.2a (modify)**: `infrastructure/postgres/migrations/0029_backfill_personal_tenant.sql` — wrap in `BEGIN; ... COMMIT;` (already done) + INSERT sentinel user BEFORE Personal tenant INSERT + re-apply 0028's NOT NULL check (idempotent). The sentinel user becomes a permanent record (documented in header).
- **11.3 (new)**: `infrastructure/postgres/migrations/0038_add_welcome_email_sent_at.sql` — `ALTER TABLE identity.users ADD COLUMN IF NOT EXISTS welcome_email_sent_at TIMESTAMPTZ NULL` (idempotent).
- **11.4 (new)**: `infrastructure/postgres/migrations/0039_add_consent_columns.sql` — `ALTER TABLE identity.users ADD COLUMN IF NOT EXISTS terms_accepted_at TIMESTAMPTZ NULL, privacy_accepted_at TIMESTAMPTZ NULL, consent_ip INET NULL` (idempotent).
- **11.4 (new)**: `infrastructure/postgres/migrations/0040_add_cookie_consent_columns.sql` — `ALTER TABLE identity.users ADD COLUMN IF NOT EXISTS cookie_consent_accepted_at TIMESTAMPTZ NULL, cookie_consent_choice SMALLINT NULL` (idempotent).

All migrations land through the standard EF Core mechanism + `docker-entrypoint-initdb.d/*.sql` (verified via Testcontainers in Wave 10.1's `test-integration` CI job + Wave 10.4's `scripts/verify-migration-order.sh`).

**No data migration** is needed. No backfill of historical users for GDPR (existing data is forward-only compliant under the new policy — right-to-be-forgotten only fires on new DELETE requests).

**`audit.events` schema is NOT modified.** The `AuditAction.Deleted` enum value (used since Wave 9's `ImportJob` cascade) is reused for the user-deletion event. The new sentinel user creation emits a `Created` audit row (existing enum value).

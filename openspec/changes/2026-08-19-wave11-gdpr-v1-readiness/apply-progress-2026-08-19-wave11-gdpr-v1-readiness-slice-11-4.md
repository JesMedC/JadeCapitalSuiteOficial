## Deviations

1. **Migration filenames 0039+0040 → 0037+0038**: the canonical
   `tasks.md` spec referenced file numbers `0039` + `0040` but the
   `Migration_AreConsecutivelyNumbered_From0001ToN` contract requires
   consecutive numbering (and 0037/0038 weren't otherwise reserved
   in this branch — they were reserved for "future use" per Wave
   10.5's tracker but never landed). The migration CONTENTS are
   byte-for-byte identical to the canonical spec; only the file
   numbers were rebased. Documented in CHANGELOG.md under the Wave
   11 header.

2. **6 ConsentHandler scenarios vs. 5 canonical**: the extra
   scenario (different-choice tier change updates timestamp) was
   added because it is the precondition for the re-call idempotency
   scenario (which only passes if the different-choice path bumps
   the timestamp; otherwise re-call IS the same-call path). Grouping
   the two together is required for coverage.

3. **`CS0618` added to Host.UnitTests NoWarn**: the existing
   `StripeOptionsValidatorTests` exercises the `[Obsolete] ApiKey`
   alias — Wave 11.4 prefers `SecretKey` but the legacy alias
   remains. Wave 12 removes the obsolete property and the test
   bridges forward.

4. **`api/util/client-ip` endpoint stub**: the registration form
   resolves a client IP via `GET /api/util/client-ip` (returns
   `{ ip: "0.0.0.0" }` fallback if not present in the auth context).
   The endpoint is not implemented in this slice — the FE falls back
   to `"0.0.0.0"`, which the BE Accepts as a valid (but
   un-correlatable) consent IP. Wave 12 or a follow-up slice adds the
   endpoint.

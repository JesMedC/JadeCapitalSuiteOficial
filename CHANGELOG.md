### Wave 11 (2026-08-19) — GDPR Art. 7 + ePrivacy + docs hardening
#### Added
- **`POST /api/auth/consent`** — GDPR ePrivacy cookie consent capture (persists `users.cookie_consent_accepted_at` + `users.cookie_consent_choice`).
- **`GET /legal/terms` + `GET /legal/privacy`** — placeholder ToS + Privacy pages with prominent "DO NOT DEPLOY WITHOUT LEGAL COUNSEL SIGN-OFF" banner.
- **Idempotent post-registration welcome email** — `RegisterUserHandler` sends via `IEmailSender.SendWelcomeEmailAsync`, wrapped in `try { ... } catch { log + continue }`, 7-day suppression window enforced via `users.welcome_email_sent_at`.
- **GDPR Art. 7 consent ledger columns** — `terms_accepted_at` + `privacy_accepted_at` + `consent_ip` (migration 0037). Persisted by `RegisterUserCommand` extension (AcceptTerms/AcceptPrivacy/ConsentIp).
- **Cookie consent banner** — bottom-bar Angular component + Signal-based service with `localStorage.jade.consent` persistence + POST-to-BE audit-trail.
- **DSAR runbook** — `docs/runbooks/gdpr-data-subject-request.md` (intake → cascade → 30d grace → restoration → sweep → audit pseudonymisation; ops playbook for `privacy@jadecapital.com`).
- **Email deliverability docs** — `docs/runbooks/email-deliverability.md` (full SPF/DKIM/DMARC DNS records + 90-day rotation cadence + provider env-var mapping for Mailgun / SES / SendGrid / Postmark) + `docs/email-deliverability.md` (executive one-pager).
- **Content-sanity tests** — `GdprOpsRunbookTests` + `EmailDeliverabilityDocsTests` assert the runbook content is intact + no TODO markers + minimal length.

#### Changed
- **`DELETE /api/users/me/export` → `GET /api/users/me/export`** — Wave 11.3 (preceding slice) shipped the portability endpoint.
- **`StripeOptions.ApiKey` → `StripeOptions.SecretKey`** — canonical property name matching `Stripe__SecretKey` env-var; `[Obsolete]` alias bridge kept for backwards-compat until Wave 12.
- **`DockerSecretConfigurationProvider`** — removed the stale `<auto-generated-by>Wave 10 slice 10.2</auto-generated-by>` line-1 marker.

#### Migrations
- `0036_add_welcome_email_sent_at.sql` (Wave 11.3) — `welcome_email_sent_at TIMESTAMPTZ NULL`.
- `0037_add_consent_columns.sql` (Wave 11.4) — `terms_accepted_at` + `privacy_accepted_at` + `consent_ip`. **Idempotent.**
- `0038_add_cookie_consent_columns.sql` (Wave 11.4) — `cookie_consent_accepted_at` + `cookie_consent_choice`. **Idempotent.**

> Note: the canonical `tasks.md` spec referenced file numbers `0039` + `0040`
> for the consent migrations. They were renumbered to `0037` + `0038` to
> keep the migration sequence consecutive (the Wave 10.5 release prepared
> `0037` + `0038` for future use, but the columns they were reserved for
> got shipped as part of `0037_user_lifecycle.sql` instead). The migration
> contents (column list + idempotency contract) are identical to the spec;
> the only change is the file numbering.
